⚙️ How the Super Agent works

1 · Message

You type one request in the chat.

→
2 · Intent detection

The Super Agent scans it for keywords, order ids and product names.

→
3 · Routing

A priority table picks ONE of the six specialized agents.

→
4 · Live data read

That agent reads the dataset at that moment (see Data Studio).

→
5 · Reply + proof

The answer carries a routing tag, an intent trace and the dataset version.

The routing priority table

Rules are checked top to bottom; the first match wins. Higher rules are more "urgent" — a return request mentioning an order id must reach Support, not Order Tracking.

#If the message has…Routed toExample
1return · refund · cancel · exchange · damaged · wrong size · payment failed🎧 Customer Support"cancel order ORD1003"
2an order id (ORD…) · track · order status · where is my order📦 Order Tracking"track ORD1001"
3price · compare · cheapest · cost · offer · deal · sale · discount💰 Price Comparison"any offers today?"
4recommend · suggest · best · gift · what should⭐ Recommendation"recommend a dress"
5stock · available · inventory · how many · left📊 Inventory"is the denim jacket in stock?"
6any product, brand or category name🔎 Product Discovery"show me jeans"
7help · support · contact · human🎧 Customer Support"I need help"
8a greeting, or nothing recognizable🤖 Super Agent itself"hello" / fallback

How product matching works

  • Each product carries a keyword list ("jacket", "denim jacket", brand names, its category).
  • Matching is whole-word, so "headphones" can never match a "phone" keyword by substring.
  • Matches are scored: an exact phrase ("denim jacket") outranks a single shared word ("denim"), so the jacket wins over jeans.

How we know answers come from the data (grounding)

  • Agents hold no answers of their own — every number (price, stock, status) is read from the dataset at reply time.
  • Edit anything in Data Studio and the dataset version bumps (v1 → v2…). Every chat reply prints the version it used.
  • Live demo: change a stock to 0, ask the agent, watch the answer flip to "out of stock" — same question, new data.

Limitations (honest ones — good viva material)

  • Vocabulary gaps. Routing is keyword-based. "How much is the summer dress" misses because "how much" isn't in the price keyword list; "my package hasn't arrived" misses because we only listen for "order"/"track". Both are left in the Agent Lab test set as failures on purpose.
  • No conversation memory. Each message is routed on its own. After "show me jeans", asking "which is cheapest?" won't remember you meant jeans.
  • First-match ambiguity. If a sentence genuinely fits two intents, the priority table decides — it can't weigh context like a human would.
  • English keywords only. Hinglish or typos ("recomend") fall to the fallback reply.
  • Session-only data. The dataset lives in the browser; a refresh resets Data Studio edits. The cloud phase (slide 3) moves it to a real database.
  • Measured accuracy: 29/31 ≈ 93.5% on the routing test set — run it yourself in the Agent Lab.

Planned upgrades (the cloud phase from slide 3)

  • Swap the keyword router for an LLM API call — fixes vocabulary gaps and adds memory; the six agents and this UI stay the same.
  • Move the dataset to a cloud database so edits persist and all users see the same stock.
  • Host the site on a cloud service; put the agents behind an API for scalability and reliability.
